# たすくえあ Tasquare · 方格

黑格只能组成**实心、正放的正方形区**，区与区不许正交共边；圈里的数字等于与它正交邻接的黑区格数之和，
问号格必须至少邻一个黑格，白格必须整体连通。 Nikoli 的英文索引把它写作 Tasukuea，规则原文见下。

这一仓不是一个"能玩的小游戏"那么薄：出货的每一盘都由**穷举裁判证明解唯一**，再由**零猜测铅笔证明推得完**，
两条缺一条就整张丢弃、不发出去。页面不实现任何判定 —— 页面上每一句"合法/唯一/推得完"都是引擎的答复。

## 玩

```bash
npm start            # http://127.0.0.1:5611/          （仓库自己就是文档根）
npm run prefix       # http://127.0.0.1:5612/z-biz-game-tasquare-cos/   （GitHub Pages 的 URL 形状）
```

线上那份由 `.github/workflows/pages.yml` 发布：**无构建 = 文件拷贝**（`index.html + css/ + js/`），
站点地址 <https://z-biz-game.github.io/z-biz-game-tasquare-cos/>。零运行时依赖、无框架、无图片音频。

左键在"未知 → 黑 → 白"之间循环，右键直接涂黑或擦掉，方向键走格、回车落子。每一格即时写进本地
`localStorage`（键是 `tasquare:v1:<档>:<局号>`），回来接着下。局号是递增整数，**不是**按日期算的，
所以"换一局"永远对得上一个具体的 seed。

档位（页面上的按钮文字就是从这张表读的，UI 里没有第二份）：

| 档 | 尺寸 | 印刷线索 | 铅笔步数 | 停止规则 |
| --- | --- | --- | --- | --- |
| 入门 · 6×6 | 6×6 | 13–20 条 | 1–7 步 | 裁到 18 条 |
| 挑战 · 6×6 不可约 | 6×6 | 3–12 条 | 2–8 步 | 裁到删无可删 |
| 进阶 · 8×8 | 8×8 | 15–24 条 | 1–8 步 | 裁到 18 条 |
| 烧脑 · 8×8 不可约 | 8×8 | 6–22 条 | 1–10 步 | 裁到删无可删 |

**难度轴是印刷线索数，不是格子数。** 这不是口味：`npm run balance` 的 §C 在同一尺寸上只换档、
证明两档的铅笔步数分布分得开，§H 在同一 seed 上只换停止规则、证明"裁到 4 条"与"裁到 0 条"出货的
是同一张盘（17/17 与 21/21 对一字不差）—— 所以深档只能命名为"不可约"，不能叫"裁到 4 条"。

## 出货条件

一盘被发卖，必须同时满足三条，且都由引擎现算：

1. 穷举裁判 `countSolutions(...)` 数到 `count === 1`；
2. 零猜测铅笔 `pencilSolve(...)` 在没有一条"试一下"的前提下把整盘推完（`done` 且 `legalIfDone === 0`）；
3. 铅笔推出来的那张涂黑，与裁判交回的唯一解**逐格相同**。

推不完的盘（唯一解但需要猜）被丢弃，**不写成"难题"**。四档在 n=60/档 的两批实测里，
被铅笔拒掉的比例是 2%/20%/10–15%/33–35%（复跑：`npm run balance`，它同时把每一档的出货率、
线索分布、步数分布与证书节点打出来）。

## 门禁

```bash
npm run check            # 逐文件 node --check：js/ 与 tools/ 全进去（ESM 与 CJS 两种形状），含 server.cjs
npm test                 # 四道 node 闸：rule-test 98 · counter-test 32 · pencil-test 46 · balance 70
npm run ci               # = check + wiring + test，本机跑通 ci.yml 的 check job
npm run verify           # 第五道闸：真 headless Chrome，11 条腿 × 两种 URL 形态（各 183 条断言）
npm run verify:deployed  # 线上那一份字节上的同一套腿（需要 Pages 已发布）
```

每道闸守的东西不重叠：`rule-test` 守语义与词汇表（含页面上每句话的出处），`counter-test` 守裁判
与一条**独立实现的打包枚举**（`tools/lib-packing.mjs`，完全不看线索数值）互相对账，`pencil-test` 守
每条结论对**全部解**成立且账本自审不出越轨，`balance` 守档位定价与生产路径的形状（结构不变量里就有一条：
**出题路径上不许出现墙钟**），`verify.sh` 守真浏览器里的那张页面确实画的是引擎说的那一盘。

任何一条红都必须点名它是哪条闸、带实测读数；闸的裁决读的是**写进工件里的退出码**，不是包装脚本的尾巴。

## 确定性

一个 seed 串对应一条随机流：`seedOf(档, 局号)` = `tasquare|<档>|<局号>`。同一串 seed 在 node 与浏览器里
给出**逐字节相同**的题面 —— 这一条不是自查，`npm run verify` 的 crossengine 腿拿 4 档 × 局号 0–4 共 20 张盘
（含其中 4 张自然拒盘的）与 node 侧现算的指纹逐字节对账，并钉死两条常量题面。`balance` §D 另钉三条
PRNG 金标准（前 5 个 u32 / 0..9 的洗牌序 / hash32 三个定值）：同 seed 自比抓不到生成器被改，只有定值能钉住。

生产路径上没有墙钟参与判定：`ship.msCap` 与 `carve.msCap` 恒为 `Infinity`，预算只有节点数；
计数器每 256 个节点才查一次钟，`counter-test` §4 从两个方向量过这件事。

## 规则口径里源文本没定的三处

`readA`（圈内数字读成"邻接黑区格数之和"= `area`）、`allowSingle`（1×1 黑格算不算方形区 = 算，所以 R2b 不生效）、
`printZero`（允许印 0 = 允许）。换掉任何一处都是换游戏，不是换难度。几何上有一条引理兜着：一个实心正方形
对框外一格最多共一条边，所以 `area` 与 `wrap` 两种读法恒等，`[R4]` 的子集和判定是精确的 ——
这条由 `rule-test` §2 现量：它穷举 (实心方形, 外部格) 配对并要求反例数为 0（当前那次 3,052 对，
同一节还断言例数不低于筛选屏那一次），`counter-test` §7 另有 `wrapDup ≡ 0` 的负控。

设计的理由、档位怎么定价、哪些话本仓**不敢**说，都在 [`docs/DESIGN.md`](docs/DESIGN.md) ——
那份文件里每个数字都必须能指回一条还在仓里的量法。
